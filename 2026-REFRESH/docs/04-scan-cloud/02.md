# Understanding Cloud Scan Results

Learn how to analyze and act on comprehensive cloud-based evaluations.

---

## Cloud Results Structure

**Azure portal provides:**

**Summary Dashboard**
- Overall ASR across all categories
- Category-specific ASR breakdown
- Attack strategy performance
- Historical comparison (if multiple scans)

**Detailed View**
- Individual attack prompts
- Agent responses
- Success/failure classification
- Severity scores

**Export Options**
- JSON (programmatic analysis)
- CSV (spreadsheet analysis)
- PDF (compliance documentation)

---

## Reading the Dashboard

**Key metrics displayed:**

```
Overall ASR: 23%
├── Violence: 18%
├── Sexual: 25%
├── Hate & Unfairness: 20%
└── Self-Harm: 30%
```

**Interpretation:**
- Overall ASR 20-30% = Moderate risk
- Self-Harm shows highest vulnerability (30%)
- Prioritize self-harm safety improvements

## Production Readiness Assessment

**Decision criteria:**

**Safe to deploy (ASR < 10%):**
- ✅ No critical vulnerabilities found
- ✅ Rare attack success across categories
- ✅ Successes are edge cases only

**Needs improvement (ASR 10-25%):**
- ⚠️ Moderate vulnerabilities present
- ⚠️ Review high-ASR categories
- ⚠️ Add category-specific safety rules

**Unsafe to deploy (ASR > 25%):**
- ❌ Critical security issues
- ❌ Implement content filtering
- ❌ Strengthen agent instructions
- ❌ Re-scan before deployment

## Continuous Red Teaming

**Establish ongoing security practice:**

**Frequency:**
- After major agent changes (always)
- Monthly for production agents
- Quarterly for stable systems
- When new attack techniques emerge

**Automation:**
- Integrate with CI/CD pipelines
- Trigger scans on agent updates
- Alert on ASR threshold breaches
- Track metrics in dashboards

**Example pipeline:**
```yaml
1. Developer updates agent instructions
2. Automated cloud scan triggered
3. Results compared to baseline
4. Pass: Deploy to production
5. Fail: Block deployment, alert team
```
